# Circle admin studio

**Artist House 0.2.0** rebrands this studio while retaining the package, native bridge, authentication callbacks and encrypted session storage. In **Banners → Daily customer notifications**, admins can enter five distinct messages, choose 1–3 daily sends and enable/pause the schedule. Apply `202610300004_daily_promotions.sql` and deploy `notification-dispatch`. Promotions are initially paused and customers must enable phone notifications and Picks & inspiration. See [release and scheduler details](../docs/artist-house-release.md).

Service editing also includes **Service name → Save name**. Verified admins can rename catalog labels (2–80 characters); stable keys and profession categories cannot be changed. Duplicate names within a profession are rejected. Updated clients use the labels in service discovery, festive/top picks and the professional service picker. Existing bookings and professionals' custom service names are preserved. Apply `202610300002_service_names.sql` after the artwork migration.

The **Services** tab manages the image for each catalog service (for example Party makeup and Festive makeup). Filter by profession, select a card, choose a photo, preview and publish. Inputs are decoded, resized to at most 1280 px, stripped of metadata through canvas re-encoding and stored as JPEG, up to 5 MB. Restore default removes the override. Apply `202610300001_service_artwork.sql` and update customer clients to use these images. Updated clients refresh within 30 seconds and keep bundled defaults or the last good images offline. No app restart or sign-out is needed after publishing. All writes require the existing verified-email admin allowlist; service artwork is public marketing material, separate from private professional portfolios.

Admin 0.1.5 adds email/password sign-in. First sign in with Google or a verified email link, then create a password. The server checks the current verified account's password status and returns only a boolean; no hash is exposed and no admin privileges are granted by password setup. Passwords are sent directly to Supabase Auth and are never saved by the app. Returning users can sign in without sending an email. Google/email-link fallback and Account → Create or change password remain available. Apply `202610230006_password_setup_status.sql`. Existing persistent sessions and native encrypted storage are preserved.

Mobile navigation follows the reference: Banners, Talent, Users and owner-only Admins. Account settings open from the header. Controls use black, white and neutral grays in both themes. The owner account `chetan.reddy@cclabs.space` alone can view current admins and approve access requests. Other Google users can request access, then tap Check access after approval. Apply `202610230004_admin_access_requests.sql` and `202610230005_admin_directory.sql`. Original professional names and the user directory are available only through guarded admin RPCs; customer-facing usernames remain unchanged.

Admin APK 0.1.4 includes the reference-based mobile screens, searchable Talent/Users, banner filters, Current admins/Requests, and persistent login. Android encrypts session data with an Android Keystore AES-GCM key; browser sessions use persistent local storage. The storage key, app origin, package ID and signing key remain stable across updates. Existing session-only storage is migrated when still present. Explicit sign-out clears stored credentials. Uninstalling, clearing app data, server-side revocation or an unrecoverable session can still require sign-in.

The Professional approvals tab lists signed-up professionals, including incomplete profiles, with All, Pending, Approved and Rejected filters. Select a profile to inspect its public details, private signed profile/work images, services and prices, and anonymous customer reviews. Approve grants the Circle tick; Reject removes it. Instagram connection grants a separate gold tick; admin approval grants a black tick in light mode or a white tick in dark mode. Both appear when both statuses apply. Disconnecting or expiration removes only the gold tick. Incomplete profiles must finish their details before review. Decisions and internal notes are stored with the admin actor and time; concurrent reviews require a refresh. Rejection affects only the admin approval badge, not the gold connection badge, publication or booking eligibility.

Apply `202610230001_professional_approvals.sql`, `202610230002_review_session_guard.sql` and `202610230003_profile_connection_badges.sql`, and deploy the updated `portfolio` Edge Function. The same verified-email admin allowlist controls banners and approvals. Profile/work storage remains private; admins receive signed image URLs lasting one hour. No user phone numbers, emails, payment details or Instagram tokens are returned to the review screen. Existing Android Admin installations need a new build to include the new tab; the local browser app serves it immediately after rebuilding.

Local web admin for finished customer-banner artwork. Run `npm ci`, `npm run build`, then `npm start` in this folder. Open **http://localhost:8090**. Build reads only the public Supabase URL and client key from `mobile/.env`; no server credential enters the browser bundle.

Use Google or an email sign-in link. First sign-in can register an account; email ownership must be verified. An account also needs an explicit entry in the server-owned banner-admin allowlist. Signing out here uses local scope and does not sign out the customer or professional app.

Upload a JPEG, PNG or WebP with its text already included, choose the header colour, destination service, schedule and priority, then publish. Recommended artwork: 1536 × 1024; maximum 8 MiB. The full image is displayed without app-added captions or overlays. Highest active priority wins; most recently updated breaks a tie. Customers refresh within 30 seconds while the app is open, and when returning to it. Pausing the winner reveals the next active campaign, including bundled fallback campaigns.

Apply `supabase/migrations/202610210001_banner_admin.sql` before running the updated customer client. An operator can approve an email using the service-role-only `grant_banner_admin` RPC. Never ship a service-role key to this panel. Configure the panel's exact origin in Supabase Auth's redirect allowlist when hosting elsewhere, and adjust the static server CSP if using a custom Supabase domain. The supplied development server binds only to this computer.

`home-banners` is a public marketing-artwork bucket. Professional profile/work media stays private. New image versions use new object names rather than overwriting cached files. Draft images are also publicly accessible to anyone with their URL; do not upload confidential artwork. Published campaign objects cannot be deleted through the panel's storage permissions.

Customer APK 0.1.14 and later includes configurable multi-profession Festive picks. In the banner editor, select the professions to display and one service per profession. Unchecked professions do not appear; no selected professions hides the cards. Apply `202610210002_banner_featured_services.sql` after the first banner migration.

The standalone Android app is **Circle Admin**, package `com.cccircle.admin`, version 0.1.4. It packages the same studio UI and uses Android's image picker, so it does not require a running localhost server or storage/camera permissions. Google sign-in opens the system browser and returns via `cccircle-admin://auth/callback` using PKCE. Add that exact redirect to Supabase Auth. Both the sign-in session and temporary PKCE verifier persist using the encrypted native store; the verifier is removed after exchange. Server-side verified-email admin permissions apply to the APK as well.

To build Android: run `npm run build`, set your Android SDK path and `CCIRCLE_SIGNING_FILE`, `CCIRCLE_SIGNING_ALIAS`, and `CCIRCLE_SIGNING_PASSWORD` in the build environment, then run `gradlew.bat :app:assembleRelease` from `admin/android`. Keep the signing key for subsequent updates. It is separate from the existing Customer and Professional keys. `npm test` verifies callback validation and session-storage boundaries.
