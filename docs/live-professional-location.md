# Available professionals: movement and background GPS

Updated 17 October 2026; release 0.1.2 / Android version code 3.

Professional GPS sharing follows the saved online preference, including while travelling between jobs after completing a session. Being busy prevents discovery pins and new immediate bookings, but does not turn off the professional's online preference. After the booking ends, an online professional can reappear at their fresh device position. Saved profile cities are never substituted for live map pins.

In the professional app, go online in Profile. An earlier explicitly paused sharing preference is preserved until the location button is used again. Work/Profile shows the current sharing status and accuracy. Tap **Allow background location** after reading the disclosure, then grant **Allow all the time** / **Always** in the device permission screen. Android shows an ongoing CC Circle location notification. Background access is configured only for the professional package; the customer app does not request it.

The registered Expo TaskManager location task can run without a React screen mounted. Native updates request high-accuracy GPS about every eight seconds, with no minimum movement required, so stationary professionals can also stay fresh. The OS controls actual delivery. GPS writes are serialised, throttled to at most one per four seconds, authenticated to the saved account and restricted by the existing server RPC to a published, online professional. Batched deliveries use the newest fix. Device fixes older than 60 seconds are rejected. Discovery only plots online, non-busy GPS rows updated within 90 seconds.

Going offline, signing out or revoking permissions stops access or updates. Offline explicitly stops the native service, disables its persisted preference, waits for any in-flight write, then clears the discovery pin. A late callback cannot restore that pin. Navigating between Work, Events, Bookings and Profile or minimising an authorised app does not stop sharing. A force-stop, device power restrictions, suspended browser, disabled GPS or network loss can interrupt updates; expired pins disappear. Reopen the app to restart after an OS termination. This is not a guarantee of tracking through force-stop.

Without background permission, foreground sharing remains available. Browser GPS watches work across tab switches while the browser permits execution, with a fresh-position heartbeat every 25 seconds. Browsers require HTTPS or localhost. Browser execution and timers can be suspended.

Customer discovery refreshes every five seconds while active. Rider pins interpolate only between received coordinates; they do not invent motion or extrapolate. Existing marker nodes are updated instead of recreated on every response. The discovery camera does not refit merely because a professional moves, preserving the customer's pan/zoom. It frames new/removed professionals and supports explicit recentering. Registered service areas remain labelled separately when GPS is missing. Reverse lookup uses the actual fix and reported uncertainty. Mapbox still renders maps/routes; Google Places still handles typed venue search.

Loading improvements: polling retains existing content and only shows an initial-load spinner, overlapping reads are deduplicated, explicitly namespaced in-memory profile/bookings/services/availability/discovery caches survive navigation, and switching accounts or signing out clears the caches. Same-account token refresh preserves them. The professional location card and work/profile screens share one profile read. Total earnings refreshes every minute rather than every fifteen seconds. No account or message data is cached on disk by this resource cache.

Booked journey sharing remains a separate participant-only lifecycle; this change adds background **discovery presence**, not a replacement navigation service. No database migration is needed: the existing location RPC and freshness/busy filters enforce visibility.

Validation: TypeScript; 55 mobile and 18 database tests. Background-task fixtures cover consent, denied permission, mounted-screen independence, newest fix selection, signed-out identity rejection, offline late-write ordering and browser movement. Resource tests cover deduplication, quiet refresh, retained content on network failure and sign-out clearing. The mocked two-tab browser flow confirms one initial professional profile read, movement before booking, preserved marker nodes, no discovery/professional refresh loading flashes and GPS continuing across professional tab navigation, with no runtime errors or real backend mutations. Physical Android background/battery and permission-screen checks still need an installed device.

Expo's [Location documentation](https://docs.expo.dev/versions/v57.0.0/sdk/location/) describes background permissions, foreground-service configuration and OS termination limits. Task registration follows the [TaskManager documentation](https://docs.expo.dev/versions/v57.0.0/sdk/task-manager/).
