## Security and operating details

- Never put Cashfree secrets or Supabase service-role/secret keys in mobile `EXPO_PUBLIC_*` variables.
- The package excludes actual `.env` files, cached CLI login metadata, generated truststores and signing credentials. Transfer any required values separately through a trusted secret-management channel.
- Every Edge Function validates its own authentication, webhook signature or worker secret even though `verify_jwt=false` is set in `supabase/config.toml`.
- Payment completion is confirmed server-side against Cashfree. Native SDK callbacks alone never mark a booking paid.
- Bookings snapshot pricing; request submission rejects a changed expected price. Orders, refunds and transfers use stable identifiers for retry safety.
- Private actor/casting information remains private. Precise journey coordinates are limited to booking participants and active journeys.
- Location sharing is opt-in and foreground-only; it stops on backgrounding or leaving the journey screen.
- Beneficiary registration sends bank details to Cashfree; the app database retains only the beneficiary identifier and environment.
- Sandbox payment success webhook URL, once the database is ready: `https://jssxdolqlnharkxatvqe.supabase.co/functions/v1/cashfree-webhook`.
- Refund and payout workers require trusted POST scheduling using the server worker secret. No schedule has been configured. Cashfree Payouts may need its IP/signature requirements addressed for the hosting environment.
